👩‍🏫 User Experience – What Users Experience in This VLAN Network

Imagine you are a student sitting at PC0 in the computer lab. You are assigned to VLAN 10 (Student). Your computer has an IP address 200.200.200.2 with gateway 200.200.200.1. You can ping other student PCs like PC3 (200.200.200.3) and PC6 (200.200.200.4) without any issue — they are in the same VLAN. But when you try to ping the teacher's computer (PC1 in VLAN 11) or the staff PC (PC2 in VLAN 12), the ping fails. You see "Request timed out". As a user, you don't know why — you just realize you can't reach those departments.

However, when the network administrator enables the router (Router-on-a-Stick), suddenly you can ping PC1 (Teacher) and PC5 (Staff) successfully. You can access shared resources across departments. From your perspective, the network just "started working" across groups. Behind the scenes, the router is routing between VLANs using sub-interfaces. This is exactly how large organizations separate traffic (finance, HR, engineering) but still allow controlled communication when needed. As a user, you only notice that after the router is turned on, inter-department collaboration becomes possible — all without changing any settings on your PC.

✨ Key takeaway: VLANs create logical separation, and inter-VLAN routing (router-on-a-stick) enables controlled communication. Users experience either isolation or connectivity based on router configuration.

Router OFF — intra‑VLAN only (Student↔Student, Teacher↔Teacher, Staff↔Staff)

📝 Step-by-Step Implementation

1 Set Up the Topology

Open Cisco Packet Tracer

Add devices to workspace:

  • Click bottom toolbar → Routers → Drag 1 Router 2911 device
  • Click bottom toolbar → Switches → Drag 4 Switch 2960-24TT devices
  • Click bottom toolbar → End Devices → Drag 9 PCs (PC0 through PC8)

Position them as shown in Figure 9.1 (page 64)

Connect the devices:

  • Use the "Automatically Choose Connection Type" cable (copper lightning bolt icon)
  • Connect PC0, PC1, PC2 to Switch1
  • Connect PC3, PC4, PC5 to Switch2
  • Connect PC6, PC7, PC8 to Switch3
  • Connect all switches to the Router's GigabitEthernet0/0 interface using trunk links
💡 For better understanding: Each switch connects to the router via a trunk port that carries all VLAN traffic (VLAN 10, 11, 12). This is called "Router-on-a-Stick" topology.
📌 Like Figure 9.1 (page 64): Topology with router, switches, and 9 end devices
2 Create VLANs on All Switches

Click on Switch1 → CLI tab

Enter these commands to create VLANs:

Switch> enable
Switch# configure terminal
Switch(config)# vlan 10
Switch(config-vlan)# name student
Switch(config-vlan)# exit

Switch(config)# vlan 11
Switch(config-vlan)# name teacher
Switch(config-vlan)# exit

Switch(config)# vlan 12
Switch(config-vlan)# name staff
Switch(config-vlan)# exit

Repeat the same VLAN creation on Switch2, Switch3, and Switch4

Switch# show vlan brief → VLANs 10, 11, 12 appear as active
📌 Like Figure 9.2 (page 65): VLAN creation and verification
3 Configure Access Ports for PCs

On Switch1 (connected to PC0, PC1, PC2):

Switch(config)# interface fastEthernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config-if)# no shutdown
Switch(config-if)# exit

Switch(config)# interface fastEthernet 0/2
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 11
Switch(config-if)# no shutdown
Switch(config-if)# exit

Switch(config)# interface fastEthernet 0/3
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 12
Switch(config-if)# no shutdown

On Switch2: Assign PC3 to VLAN 10, PC4 to VLAN 11, PC5 to VLAN 12

On Switch3: Assign PC6 to VLAN 10, PC7 to VLAN 11, PC8 to VLAN 12

📌 Like page 66: Access port configuration for each VLAN
4 Configure Trunk Ports (Switch-to-Router)

On each switch, configure the uplink port connecting to the router:

Switch(config)# interface fastEthernet 0/4
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,11,12
Switch(config-if)# switchport trunk native vlan 99
Switch(config-if)# no shutdown
Switch(config-if)# exit
Switch# show interfaces trunk → Verifies trunking status and allowed VLANs
📌 Like Figure 9.3 (page 67): Trunk port verification output
5 Configure Router-on-a-Stick (Sub-Interfaces)

Click on Router → CLI tab

Enter these commands to configure sub-interfaces for each VLAN:

Router> enable
Router# configure terminal
Router(config)# ip routing
Router(config)# interface gigabitEthernet 0/0
Router(config-if)# no shutdown
Router(config-if)# exit

Router(config)# interface gigabitEthernet 0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 200.200.200.1 255.255.255.248
Router(config-subif)# exit

Router(config)# interface gigabitEthernet 0/0.11
Router(config-subif)# encapsulation dot1Q 11
Router(config-subif)# ip address 200.200.200.9 255.255.255.248
Router(config-subif)# exit

Router(config)# interface gigabitEthernet 0/0.12
Router(config-subif)# encapsulation dot1Q 12
Router(config-subif)# ip address 200.200.200.17 255.255.255.248
Router(config-subif)# exit
Router# show ip interface brief → Sub-interfaces are up with IP addresses assigned
📌 Like Figure 9.4–9.5 (pages 67-68): Sub-interface configuration and verification
6 Configure PC IP Addresses

Configure each PC with static IP address:

  • PC0 (Student): Click on PC0 → Desktop → IP Configuration → Static → IP: 200.200.200.2, Subnet Mask: 255.255.255.248, Default Gateway: 200.200.200.1
  • PC1 (Teacher): IP: 200.200.200.10, Gateway: 200.200.200.9
  • PC2 (Staff): IP: 200.200.200.18, Gateway: 200.200.200.17
  • PC3 (Student): IP: 200.200.200.3, Gateway: 200.200.200.1
  • PC4 (Teacher): IP: 200.200.200.11, Gateway: 200.200.200.9
  • PC5 (Staff): IP: 200.200.200.19, Gateway: 200.200.200.17
  • PC6 (Student): IP: 200.200.200.4, Gateway: 200.200.200.1
  • PC7 (Teacher): IP: 200.200.200.12, Gateway: 200.200.200.9
  • PC8 (Staff): IP: 200.200.200.20, Gateway: 200.200.200.17
All PCs use subnet mask: 255.255.255.248 (/29)
📌 Like Figure 9.2 (page 64-65): PC IP configuration for each VLAN
7 Test Connectivity (Intra-VLAN & Inter-VLAN)

Test Intra-VLAN Connectivity (Same VLAN):

PC0> ping 200.200.200.3 → Successful (both in VLAN 10)
PC1> ping 200.200.200.11 → Successful (both in VLAN 11)

Test Inter-VLAN Connectivity (Different VLANs) - Router OFF:

PC0> ping 200.200.200.10 → Request timed out (Router OFF)

Click "Router ON" button above to enable inter-VLAN routing, then test again:

PC0> ping 200.200.200.10 → Reply received! (Router ON)
✅ Success! When router is ON, all PCs can communicate across different VLANs. When router is OFF, only same-VLAN communication works.

💡 Educational Insight: This lab demonstrates VLAN segmentation (broadcast isolation) and the necessity of a Layer 3 device (router) for inter-VLAN communication. The router-on-a-stick method uses 802.1Q trunking to carry multiple VLANs over a single physical link.
